# 验证与手动验收

## 自动检查

```bash
npm ci
npm test
npm run build
npm run music:fetch
npm run cues:prepare
```

测试只收集当前目录的 `src/**/*.test.ts`，避免工作区中的另一份项目被重复执行。测试覆盖：握拳音效首次识别与防重复、握拳稳定门限、X 计时、左右映射、动作平滑、状态机恢复、音频静音 / 切换 / 页面可见性，以及摄像头异步初始化失败与重试。

`music:fetch` 校验每首 MP3 的大小与 SHA-256；它不对音质或听感评分。音频通过 ffprobe 验证为可解析的 MP3。构建检查包括 TypeScript 和 Vite 静态产物，不等于真实摄像头验收。

## 浏览器验收步骤

### 手动模式与界面

1. 打开首页，从「无摄像头，使用操杆」进入。确认三个角色均可加载，三根杆能分别控制身体和双臂。
2. 用 `Tab` 聚焦操杆，验证方向键、`Shift` + 方向键和 `Home`；触屏上从按钮开始拖动，检查页面不会随拖杆滚动。
3. 依次切换中文、English、Bahasa Melayu。检查配乐控件、错误提示、弹窗与辅助标签，刷新后语言应保持。
4. 在桌面宽屏及约 390 px 宽的手机视口检查布局、文本换行、控件可见性与弹窗滚动。

### 音频

1. 用户点击入场后，默认曲目开始播放；从零到 100% 调整配乐音量，静音与重新开启均应生效。
2. 依次切换三首曲目，检查音频可加载；静音时切换不会自动解除静音。
3. 刷新，检查曲目、音量、静音状态保持。重新入场后才播放，首页不会自动播放。
4. 切到其他标签页，配乐暂停；回到仍在进行的体验时恢复；回首页后再切回页面不会恢复播放。
5. 打开「音乐来源与署名」，检查三首曲目署名、来源和 CC BY 4.0 链接以及未剪辑 / 整曲重复说明。
6. 临时在浏览器网络面板阻断当前 MP3 请求后刷新 / 切曲，确认显示音频错误；取消阻断后重新开启声音或选择另一首恢复。
7. 在手动模式分别点击「试听开幕」「试听闭幕」，确认两段音色、节奏不同，播放一次后停止，幕布状态不变；播放中配乐减弱，结束后恢复。
8. 连续试听两段应停止前一段；音效中途静音、切换标签页或回首页应立即停止，返回页面不会重播音效。阻断音效请求后应显示音效失败提示，恢复后重新试听可重试。

### 真实摄像头与识别

1. 在 localhost / HTTPS 上由测试者允许摄像头，确认只申请视频、没有麦克风权限。
2. 握拳时确认首次有效识别就响起开幕锣鼓，连续 8 次识别后幕布才打开，持续保持不会再响。短暂握拳后松开，确认只响音效、不打开幕布；松开至少半秒后再握拳可再次响起。双手移动时左右臂、身体位置和大小应随输入变化。
3. 双手交叉成 X，检查 3 秒进度；中途松开应清零；完整保持后响起闭幕锣鼓并合幕，等待冷却再握拳可重开。
4. 打开「瞳」，检查关键点与预览重合；切换镜像只改变显示，交换左右才改变控制侧。
5. 演出中切到手动或回首页，确认摄像头设备指示停止；模型失败或摄像头被占用时能进入手动回退。
6. 网络恢复后重试摄像头应重新初始化；模型加载中退出或改为手动后，不应出现延迟到达的摄像头流继续占用设备。

- 2026-09-26：Node.js 24.18.0 环境下，38 项单元测试通过，生产构建通过；覆盖开幕首次握拳识别、防重复及重新触发，以及锣鼓独立播放、配乐音量恢复、中止及错误重试。
- 三首原始 MP3 可由 ffprobe 解析，大小与 SHA-256 校验通过。
- 两段锣鼓成品分别为 4 秒、4.45 秒，源文件和成品校验通过。
- 浏览器中检查了中 / 英 / 马来语控件和署名弹窗、桌面与 390 px 视口布局；选曲和音量在刷新后保留。系统拒绝摄像头访问时进入手动回退。
- 真实手部识别、摄像头权限与移动设备性能须按以上步骤在目标设备实测；单元测试使用模拟媒体设备。
